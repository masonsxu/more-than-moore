Sizing Evidence

选型的数据支撑

上表每个选型都有一条可复核的量级论证（推导过程见 PART 00 §3，决策与回退条件见 PART 00 §8）：

接入：需求 10²–10³ msg/s（§3 推导）≪ Kafka 三机基准 2×10⁶ msg/s —— 余量 3 个数量级（ADR-1） 存储：原始年增 10–20 TB → 单机一年溢出 → 湖仓在 P2 引入（D-07），对象存储冷区 5 年 ≤ 25 TB 训练算力：WM 级图像模型月均 <80 GPU 时 → x4 自建够用（D-08） Day-0 极简形态：1 台 VM + Postgres + Python STDF 解析 + Grafana —— 本图是 P2 之后的形态，不是 Day-1 采购单（PART 00 §6）

Non-Functional Requirements

非功能约束（设计假设）

数据量级 单厂估算

  • WT + FT + KGSD 全年 10⁹ 行级 die 记录（10¹² 参数值级）
  • 原始 STDF 年增 10–20 TB（PART 00 §3 推导），湖仓列存压缩后 <10 TB
  • 晶圆图 E142 年百万级 XML 文档

SLO

  • 在线评分 API：P99 < 1s（自适应判定用）
  • 批表：T+1 06:00 前完成宽表与基线刷新
  • 管道月度可用性 ≥ 99.5%，回填窗口 ≤ 24h

安全与合规

  • 数据分级 L1–L4：L3 以上出厂管控、字段级脱敏
  • IP 管控：训练区数据不落地终端，导出需审批
  • 全链路审计：谁在何时用哪份数据训练了哪个模型
标准映射：STDF v4（ATE 记录）· SEMI E142（晶圆图）· IEEE 1838（堆叠测试访问） 方法论引用：湖仓 medallion 分层 · MLOps registry 审计 架构检验标准：任何模型上线不需要平台部写一次性代码
