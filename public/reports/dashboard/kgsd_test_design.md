# KGSD 测试看板设计（修订版）

> 修订说明：按可行性调研结论修订——废弃"单一通过率线""raw bin Pareto""按日期对齐程序版本"三处设计；图一改 FPY/final 双口径、图二改 first-fail 口径并加样本量护栏、图三补坐标字段与混杂检查；新增 KGSD 特有分析层、参数漂移预警与早会议程。

## 图一：通过率趋势图（FPY / final 双口径）

**要回答的问题**：今天/这周的 KGSD 测试通过率，和之前比有没有变化？变化发生在哪个时间点？和哪个变更事件对齐？

**口径定义（先于画图）**：

- **first-pass yield（FPY）**：首次插入判定的通过率，不含修复与复测回收——对工艺漂移最敏感
- **final yield**：TSV/lane 修复 + 复测/reprobe 之后的最终通过率——决定交付
- 两条线必须分开：复测回收会系统性抬高 final yield，混合一条线会把"探针接触问题"和"真实工艺漂移"搅在一起

**需要的数据字段**：

| 字段 | 含义 | 来源 |
|---|---|---|
| `date` | 日期或班次 | MES/工单 |
| `lot_id` / `wafer_id` / `insert` | 批次/晶圆/插入点（下钻主键） | MES（谱系中枢） |
| `yield_rate_fpy` | 首次插入通过率 | 测试结果统计（按 `retest_flag` 过滤） |
| `yield_rate_final` | 最终通过率 | 测试结果统计 |
| `retest_flag` | die 级复测标志 | STDF PRR PART_FLG retest 位 / WPFile 同构字段（S0 数据字典确认） |
| `test_count` | 首测 die 数 / 复测次数 | 测试结果统计 |
| `program_version` | 测试程序版本 | **MES/EAP recipe 绑定（权威）**；测试数据 MIR（JOB_NAM/JOB_REV）交叉校验；测试计划指纹（测试项序列 + 上下限 hash）为版本真值锚 |
| `flow_version` | Flow 版本 | MES 工单 |
| `device_id` | 设备编号 | EAP/机台自动化 |
| `maintenance_event` | 维护/清洗/换针卡事件 | MES/设备维护系统 |

**画法**：横轴时间，实线 FPY、虚线 final、点线目标。关键动作：版本切换点用 MES recipe 变更事件**按 lot 谱系对齐**——跨版本边界的 lot 按 insert 归属，不按日期切（日期切法必把边界 lot 错误归因）。异常日可下钻：lot/insert 清单 → 失效 die 位图。

**这张图的价值**：通用 YMS 的趋势图能给曲线和报警（广立微 DE-YMS 官方口径支持 CP/FT/WAT/Inline/Defect/WIP 多类型数据整合分析，自带异常检测报警模块）——所以价值不在图型，在**口径**：FPY/final 分线、版本按插入点谱系对齐、异常日下钻到 lot，这三件事要在数据模型里就位，YMS 现成配置给不了。

## 图二：Bin Pareto 图（first-fail 口径）

**要回答的问题**：失效的 KGSD 堆叠体里，首失效症状的构成是什么？哪个症状最近在恶化？

**统计口径（为什么不能直接数 bin）**：

- bin 顺序是 fail-stop 的（Open/Short → Idd → Function → Margin…），前一个 bin 挂了后面根本不测——raw bin 计数的 Pareto 混杂了"失效构成"和"程序停止结构"，bin1 一个 excursion 会把后面所有 bin 清零
- 以**首次插入的 first-fail bin** 为准：对每颗失败 die 取它停在哪一步；分母用失败 die 数，不用总 die 数
- first-fail 分布回答"首失效症状构成"；要各模式的边缘发生率，需程序 continue-on-fail 且测试项结果全量落盘（根治），或独立性假设下递推反解（同一物理缺陷常同时挂多个测试项，假设需验证）
- 复测让"最终 fail 集"经过存活者选择——一律用首插入口径

**需要的数据字段**：

| 字段 | 含义 | 来源 |
|---|---|---|
| `bin_id` | Bin 编号 | 测试程序 |
| `bin_name` | Bin 名称——**症状命名**（Open/Short、PowerShort、Idd、Function、Margin） | Bin 定义表 |
| `first_fail_count` | 该 bin 的首失效 die 数 | 测试结果统计（first-fail 归一） |
| `percentage` / `cumulative_pct` | 占失败 die 比 / 累计占比 | 计算 |
| `program_version` + bin 定义映射表 | 版本分段对比的前提：程序版本一变 bin 定义可能变，附映射表 | 程序发布记录 |

**画法**：柱状按 first-fail 数量降序，叠累计占比曲线。**样本量护栏**：检出 5pp 占比位移（α=0.05、power=80%）需约 690 失效/比较组；日失效数不足时自动切换 7 天滚动窗。speed bin（分档 bin）是合格分档不是失效，不进失效 Pareto。

**这张图的价值**：bin 是电学症状，不是物理根因。"TSV 开路""微凸点虚焊"是根因名——Open/Short 窗口下，seal ring 损伤、凸点 bridge、TSV 开路混在一起，症状↔根因是多对多映射。这张图回答"坏在哪个症状"，是跨部门沟通的起点；根因归因必须走补充层的空间签名 + 跨插入点差分 + FA 闭环，**作为根因结论不成立**。

## 图三：Site/Head 热力图

**要回答的问题**：同一台设备，不同 Site 或 Head 之间，通过率有没有系统性差异？差异是硬件问题还是晶圆位置图案？

**需要的数据字段**：

| 字段 | 含义 | 来源 |
|---|---|---|
| `site_id` / `head_id` | Site 或 Head 编号 | 测试程序/EAP |
| `date` | 日期或时间窗口 | 测试结果 |
| `yield_rate` | 该 Site 的通过率 | 测试结果统计 |
| `test_count` | 该 Site 的测试 die 数 | 测试结果统计 |
| `die_x` / `die_y` + 径向带 | die 坐标与 wafer 中心（STDF WCR 的 CENTER_X/Y → 归一化径向带） | 测试结果（WCR 记录） |
| `touchdown_count` | 落针次数 | EAP/探针台 |
| `clean_event` | 探针卡清洗/维护记录 | 设备维护系统 |
| `device_id` | 设备编号 | EAP |

**画法**：矩阵热力图，横轴时间，纵轴 Site/Head，单元格颜色=通过率，红（低）到绿（高）。两条纪律：

- **混杂检查先行**：multi-site 的 die→site 分配是 prober 步进 pattern 内的固定偏移，圆晶圆 × 矩形 footprint 不对称会让各 site 的 die 群体径向偏斜——先画 site × 平均径向位置关联图，确认存在偏斜再分层检验（CMH 或 logistic：site + wafer 固定效应 + 径向带）。层内仍显著 → 硬件嫌疑成立；只在层间显著 → 径向良率图案
- **聚合规则**：单 site 日 n=500 时 95% CI 半宽 ±1.7~2.1pp，-2pp 位移在单日检出边界——单元格聚到 ≥1,000 die（±1.2~1.5pp）或按周；叠 touchdown/清洗刻度，让 site 变差与清洗周期在时间轴上对齐

**这张图的价值**：site-to-site variation 是行业公认议题（针尖污染 → 接触电阻漂移 → 良率损失；Advantest APC 已产品化"按需清洗"替代固定周期）。如果 Site 3 在**层内**持续比 Site 1 低 2%，问题大概率在探针卡、测试座或该 Site 程序配置——这张图把"产品问题"和"设备问题"分离开，前提是先排除晶圆位置混杂。

## KGSD 特有分析层（三张图之外，KGSD 区别于平面测试的核心）

### A. 跨插入点差分（最重要）

谱系主键 `(lot, wafer, x, y, insert, 测试序号)`（wafer_id 作键而非 lot——split lot 使两者非一一对应；测试序号处理同 insert 内 reprobe）；(x,y) 经 WCR 归一化到统一 die index（各插入点 prober 原点/方向/notch 不同，键合翻面后更甚）；die→stack 组成关系从 MES/键合 map 取，测试数据里推不出来。

产出："CP 过 → KGSD 挂"清单 = 给键合/减薄工序的工单；"CP 就挂" = 裸片类。

前提：上游 CP 逐 die 数据可能归属客户（数据主权）——需客户数据共享协议兜底，至少保住 KGD 标记位。

### B. 堆叠层级归因

per-layer fail rate——base die 挂，上面全报废，是整堆产出的乘数。良率复利放大系数：单 die 良率 -1pp → 12 层堆栈 -6.4pp、16 层 -6.9pp（0.95¹²=54.0%→0.94¹²=47.6%；0.95¹⁶=44.0%→0.94¹⁶=37.2%）。这是"为什么单层监控不够"的定量论证。依赖 MBiST 逐层失效记录与各键合阶段谱系完整；属工程/周级视图，不进早会。

### C. 口径四件套

first-pass yield / final yield / **escape rate**（KGSD 过但下游 FT/SLT 挂 = KGD escape；每 die 100 DPPM 独立失效假设下 16 层堆叠逃逸约 1600 DPPM）/ **repair 口径**——repair 率不等于 repair 余量：通过但吃掉大半冗余（冗余仅占裸片面积 5–10%）的 die 是下游风险件，需监控冗余消耗度分布。

### D. 空间签名自动分类

失效位图按点/边环/列/聚簇自动归类（SPR 思路），输出"疑似 SealRing / 疑似 TSV / 疑似键合"分布报表，直接对应不同责任工序。分类规则需 FA 闭环标注喂养；工程触发式/周级。

### E. 参数漂移预警（早于良率塌陷的最早信号）

接触电阻、Idd、Vmin、修复位图计数的直方图漂移先于良率塌陷。关键测试项直方图 + 分位数控制图（按 lot 分层），异常时先于良率触发归因。

## 每天早会看什么（T+1 09:00 日报，10–15 分钟）

前提：全部阈值自动判定、只看例外——人工过数必超时，自动化程度决定早会时长。

| 序 | 议程 | 时长 | 内容 |
|---|---|---|---|
| 0 | 昨日行动项闭环 | 2 min | 先过昨日闭环再开新火 |
| 1 | 24h excursion / OOC | 3 min | 良率越界、SPC 判异——今天必须行动的火 |
| 2 | 良率总览（含 site 下钻） | 3 min | 产品 × 插入点 × 机台 FPY vs 目标 vs 7 天基线；热力图是机台维度下钻，不是独立议程 |
| 3 | first-fail bin 占比位移 | 2 min | vs 7 天基线；min-n 护栏，未达自动切滚动窗——工艺变更最早信号 |
| 4 | 复测率 / 修复率 / 冗余消耗 | 1 min | reprobe 突升 = 探针/接触或程序问题；冗余消耗度右移 = 下游风险 |
| 5 | 参数漂移 top3 | 1 min | 分析层 E 的输出 |
| 6 | MRB / 失效件处置队列 + hold lot | 2 min | KGSD 失效件单价极高，处置积压是每天的运营现实 |
| 7 | WIP / 等测产能约束 | 0.5 min | 备注级（plan 同步），不占数据早会主线 |

**阈值护栏（统计自洽版）**：

| 规则 | 护栏 |
|---|---|
| 单日良率 < 目标 −1.5pp | 3σ 检出需日测约 1,540 die/产品/插入点；日测 <1,500 时改用 p 图/Laney p′ 按 n 重算限，不用固定阈值 |
| bin 占比 > 基线 +2σ | 基线 ≥20–25 个点（7 点基线的 σ 估计相对波动约 29%，控制限本身不稳）；7 个 bin 日度同时判异假报警约 28%/日 → FDR 或 Bonferroni（α/7），或写明接受为人工过滤的粗筛 |
| bin 占比新增 ≥5pp | 约 690 失效/比较组（下界；失效空间聚集使有效 n 更小，上线前用厂内数据估 design effect 重校） |

以上 CI 计算假设 i.i.d. 二项，在失效聚集下全线偏乐观——正式上线前用厂内数据重校。

## 这三张图的共同逻辑

每一张都对应一个明确的行动，且每一条结论都带统计护栏：

- 通过率趋势（FPY/final 双口径）→ 触发归因（哪个版本、哪个事件，按 lot 谱系对齐）
- Bin Pareto（first-fail 口径）→ 触发症状级排查，根因走分析层闭环
- Site 热力图（排除位置混杂后）→ 触发设备检查（探针卡/清洗周期）

找 IT 要数据接口时，要的不是"三张图的画图权限"，而是按字段清单把谱系主键、复测标志、坐标与清洗计数接进来——口径在数据模型层就位之后，图只是查询的结果。
