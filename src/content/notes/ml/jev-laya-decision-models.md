> 定位说明：本文是 **ML 模块第三篇**。第一、二篇（[时序复现](/notes/ml/cnn-transformer-time-series/)、[产线耦合失效预警](/notes/ml/cnn-transformer-advanced-packaging/)）处理的是传感器数值序列；本篇处理另一类数据——**产线里的文本判断**（报警处置、FA 路由、来料审核、copilot 路由），对应的模型是 2026-09 发布即刷屏的两个"System One 决策模型"：TypeSafe 的闭源 **Jev**（9-15）与 Convai 的开源 **Laya**（9-18）。结论先行：**方向是真的（"判断"独立成层），但两个模型当前都是 v1 形态；对先进封装厂，近期落地点是"非关键路径的文本判断分流 + 制造 copilot 架构层"，图像与产线主链路不适用；数据合规约束下 Laya 本地微调是主路径。**

## 一、两个模型是什么

### 1.1 共同的品类定义：System One 决策模型

不生成文本。输入一段状态（`state`，非结构化文本/JSON）+ 一组预定义类型的判断题，一次前向并行返回全部答案，每个答案带概率分布。三个判断原语两家一致：

| 原语 | 回答什么 | 返回 | 限制 |
|---|---|---|---|
| Choice | 从给定选项里选一个 | 选项 + 全分布 + confidence | Jev ≤255 选项；Laya >20 选项即明显劣化 |
| Score | 在有序等级上打分 | 期望分 + 各档分布 + confidence | 2-10 级 |
| Noul | 一个陈述是否成立 | P(yes) ∈ [0,1]，无 confidence 字段 | 想量化程度用 Score |

与 LLM 的本质区别：无自回归解码循环，所有答案单次前向直接从概率头读出——这是"快 + 输出免费"的来源，也是"不会输出类型外的值"（官方称"零幻觉"，准确说是**类型安全**：不会编造选项/字段，但仍会在选项内高置信度地选错）的来源。

命名均非随意：Jev 取自经济学家 Jevons（杰文斯悖论——判断效率提高几个数量级后，判断调用量反而爆炸）；品类名 System One 取自卡尼曼《思考，快与慢》的系统 1。

### 1.2 Jev（TypeSafe AI，2026-09-15，闭源 API）

| 维度 | 数值（口径见来源分级） |
|---|---|
| 发布方 | TypeSafe AI；创始人 Diogo Almeida 为 InstructGPT / RLHF 论文共同作者；DCVC 领投 $40M 种子轮 |
| 接口 | `POST api.typesafe.ai/v1/systemone`；也上 OpenRouter / Vercel AI Gateway |
| 延迟 | 官方 70-500ms；第三方实测 p50 236-276ms；官方"快 40-200 倍/便宜 444.6 倍"为自家 workflow 最优值，独立实测达不到 |
| 价格 | 输入 $0.042/MTok，输出免费；新账号送 $5 |
| 上下文 | 单请求 64k token（state + 最长单题 ≤32k） |
| 训练 | RLCD（面向校准决策的强化学习），细节未公开；官方自述数据 100% 合成 |
| 准确率 | 自家 workflow 基准 67.8%（最强 LLM 基线 74.1%）；OpenRouter 用 Banking77（3080 条真实客服语料）实测 81.0%（Claude Opus 5 为 84.4%）——**不比 LLM 更准，卖点只是快和便宜** |
| 语言 | 英语最好，中日韩"能处理但不一样好"，中文需自测 |
| 架构（逆向，B 级证据） | Archer Hume 用 1 万次 API 调用逆向：分类头 + 共享前缀推理（state 编码一次多题复用），MMLU 1200 题上 ECE 0.0313；后端疑似稀疏 MoE；Salfati 复核确认其中 41/49 条论断。TypeSafe 未确认 |

生态热度（A 级，可查证）：发布当天 HN 1863 分；Vercel 上线 24h 内 13% 付费团队接入；LangChain 9-20 发布 Jev-as-a-Judge 实验（单次评分 0.44s / $0.00035）；Vercel AI SDK 7.0.105 新增 `experimental_evaluate` API，Jev 是第一个原生接入模型；谷歌 Gemma 官方 9-20 发帖把 DiffusionGemma 适配成 Jev 式接口。

### 1.3 Laya（Convai Innovations，2026-09-18，Apache 2.0 开源）

| 维度 | 数值 |
|---|---|
| 发布方 | 独立研究者 Nandakishor Mukkunnoth；基于其 2025 年两篇论文（arXiv:2503.23303、arXiv:2510.01237）重构；社区称"开源版 Jev"，接口几乎一一对应 |
| 架构 | ModernBERT-large 编码器 395M + 决策头约 25M（2 层 Transformer：选项打分头 + 低置信上交门控），共 421M，全公开 |
| 检查点 | `laya`（英文 421M，默认上下文 512）/ `laya-multilingual`（mmBERT-base 322M，1024，宣称 100+ 语言）/ `laya-typed-decisions`（421M，1024，基准微调版）；编码器上限 8192 但延迟与质量未验证 |
| 延迟 | T4 单问题 p50 32.8ms；10 题 batch 共 72.3ms（7.2ms/题）；M3 Max（laya-mlx 移植）约 60 次/s、内存 ~1GB；**无 GPU 的弱 VPS 热 predict 可达 49.4s——交互场景必须有 GPU** |
| 训练 | RLCD 实现全公开：严格适当评分规则（对数 + 球面 + 排序概率评分 RPS 组合）做 reward，GRPO 风格组基线策略梯度，不用交叉熵；微调 Notebook 可在 Kaggle 免费 2×T4 跑（约 3 万问题、4 epoch、4-5h） |
| 准确率 | typed-decisions 微调版 0.766（**base 零样本仅 0.362，低于多数类基线 0.461**）；AG News 4 分类 0.950（Jev 0.910）；Banking77 77 类 0.425（Jev 0.870）——**选项 >20 断崖** |
| 校准 | 裸 ECE 0.466 → 自有分布上温度重拟合后 0.081；多语言版出厂未带拟合温度 |
| 语言路由 | 内置 Router <1ms 检测文字系统（22 种）自动切换检查点；45/51 语言可用。存在翻车案例：英文版在高棉语上准确率 0、置信度 0.952——**置信度阈值拦不住"自信地错"，必须先路由** |
| 热度 | GitHub star 数三天破 6000，截至本文核对约 2.09 万；接口三天内 0.1.0→0.3.4，锁版本是硬要求 |

### 1.4 选型对比（合并口径）

| 维度 | Jev | Laya |
|---|---|---|
| 开源/部署 | 闭源，仅美国西海岸云 API（企业版可谈 ZDR） | Apache 2.0，本地/私有云/离线，T4 / Mac MPS 可跑 |
| 零样本 | 强，开箱即用 | 弱（0.36），必须微调 + 校准 |
| 长上下文 | 64k | 默认 512/1024（长 8D 报告、agent trace 装不下） |
| 宽选项 | ≤255 | >20 劣化 |
| 多语言 | 英语优先 | 45/51 语言 + 自动路由 |
| 数据出境 | 出境（跨境 RTT 150-300ms 还吃掉延迟优势） | 不出境 |
| 定制 | 只能靠 state/问题措辞调 | 自有数据微调（fab 的历史处置记录就是现成标注） |
| 成本 | 每日 1 万次 × 1k token ≈ $0.42/天 | 一张 T4 约 $360/月（0.5/h × 720h），含运维 |

**成本不是选型理由**（两边都便宜到可忽略）；决定性因素是数据合规、延迟预算、可定制性。

## 二、影响封装厂使用的四个工程事实

1. **纯文本输入。** 两个模型都不吃图像/音频。AOI、SEM、X-ray、超声扫描不能直接进——这条路线仍归 CNN/VLM（本模块第一、二篇已覆盖时序侧，VLM 待另篇）。凡是数值可算的（上下限比较、计数、日期先后）官方明确建议交给代码，Jev 1.13 已知弱点清单里就包括计数与日期比较不可靠。
2. **confidence 不是正确率。** Jev 的 confidence 是分布峰度的确定性变换：`c = (K·p_top − 1)/(K − 1)`，不含分布外信息；校准是群体性质——"置信 0.8 的集合约 80% 正确"，不保证单点。**自动执行前必须在自有数据上重新校准（Laya 裸 ECE 0.466 就是警告），并设阈值转人工。**
3. **无解释输出。** 不产推理链，纯概率黑盒。受审核/追溯约束的环节（放行、报废、客户通知）只能做"建议 + 决策权留人"，且要记录完整调用日志（输入、检查点版本、分布、阈值）。
4. **双方 headline 数字都挑过口径。** Jev 的 193.6 倍/444.6 倍来自自家测试集；Laya 的 0.766 来自用 benchmark 训练集训出的微调版，且 Jev 那列是第三方数据拼接，两边从未同链路对比。**任何封装域结论都需 50-100 条自有标注样本先测。**

## 三、先进封装场景映射

按[路线图](/notes/smart-mfg/data-science-roadmap/)的工序链（减薄 → TSV → 微凸点 → 堆叠键合 → 塑封 → CP → PSWT → KGSD → 检查量测 → 2.5D 组装）逐类判断。适用判据：输入可文本化、答案是封闭选项、人读几秒能判、判断错了可回退。

### 3.1 可用场景（按可行性排序）

| # | 场景 | 判断原语 | 数据源 | 现状痛点 | 可行性 |
|---|---|---|---|---|---|
| 1 | **制造 copilot 架构层**（模型路由/工具调用门槛/LLM 输出验收） | 三原语混用 | copilot 内部状态 | 现在每个判断都烧 LLM token，延迟与成本叠加 | **高，无标注即可起步**。这是 Jev 文档列明的三大用法，与行业生态（LangChain/Vercel）已验证的路径一致 |
| 2 | **SPC/FDC 报警分诊**（S2→S3 衔接点） | Noul(是否 actionable) + Choice(处置类别) | EDA/FDC 报警事件 + 机台/腔体/参数/规则上下文文本化 | 报警量大、误报多，工程师逐条看；规则引擎死板，LLM 每条几百 ms 且贵 | **高**。每日几百条 × 1k token 的量级对两个模型都是轻负载；Laya 微调后 33ms/条支持近线批处理 |
| 3 | **FA 流程路由** | Choice(分析流程：切片/SEM/EMMI/X-ray/FIB…) | binning 摘要、客退描述、失效现象记录 | 依赖 FA 工程师经验分派，返工率高 | **中高**。taxonomy 常超 20 类 → Laya 需拆两级（先大类后小类）或用 Jev；历史 FA 记录是现成标注 |
| 4 | **MRB/异常批处置建议** | Choice(放行/让步/挑批/返工/报废) + Score(风险等级) | 8D 报告、批次谱系摘要、历史同类案例 | 处置会依赖资深工程师 | **中**。只能做建议+低置信转人，决策权留人（见 2.3 无解释约束）；8D 全文超 Laya 默认上下文，需摘要或选 Jev |
| 5 | **来料/供应商审核** | Noul(是否超规) + 代码 | 基板翘曲 COA、材料批次报告：数值部分代码判，供应商偏差说明等文本部分模型判 | 人工逐份读报告 | **中**。混合管道（代码算数值 + 模型判语义）是标准做法 |
| 6 | **RAG/知识库检索过滤与重排** | Noul(片段相关) | 工艺文件、SOP、历史案例库 | 检索噪声直接影响 copilot 质量 | **中**。RAG rerank 是社区已验证用法，但中文工艺文档需自测（见 2.1 语言限制） |

### 3.2 不适用场景（边界同样重要）

| 场景 | 为什么不适用 | 替代路线 |
|---|---|---|
| AOI/SEM/X-ray 缺陷分类 | 纯文本输入限制 | CNN/VLM（另篇） |
| 规格判定、计数、日期比较 | 数值可精确计算，模型反而不可靠（Jev 官方已知弱点） | 代码/SPC 规则 |
| 良率根因分析、工艺窗口优化 | 多步推理（System 2），决策模型按定义不参与 | LLM + 分析工具 + 人 |
| 报告/摘要/SOP 生成 | 生成类任务 | LLM |
| 键合过程实时控制回路 | 伺服环 ms 级闭环；33ms 也只是"环外判断"，且这类模型不该进控制环 | FDC/传统控制 |

### 3.3 与 L0-L4 阶梯的关系

路线图 L3（模型给出量化建议）→ L4（建议进入受控执行）之间的每个"受控执行"都需要门控判断（要不要执行、置信够不够、要不要升级给人）。以前这类门控要么用死规则（误伤）要么用 LLM（贵且慢），这正是杰文斯悖论命名的立意：**判断成本降到厘级、延迟降到几十 ms 后，以前"不值得自动化的小判断"变得值得了**——两个模型服务的是 L3→L4 的门控层，不是替代 L2/L3 的统计与预测模型。

## 四、可行性分级与落地条件

### 4.1 选型决策树（按硬约束顺序）

```
1. 数据能否出厂境（fab 数据分级 L1-L4、客户 IP）？
   └─ 不能 → Laya 本地部署（硬约束，后续全部围绕它）
   └─ 能（仅限脱敏/公开文本，如 copilot 对公开文档）→ Jev 可作零样本起点
2. 有无历史标注（处置记录、FA 分派记录）？
   └─ 无 → 先积累 50-100 条，别急着训
3. 输入是否超 1k token（长报告/trace）？
   └─ 是 → Jev（64k）或 Laya + 分块摘要
4. 选项是否超 20 类？
   └─ 是 → Jev，或 Laya 两级分层
5. 是否需要中英混杂文本（厂内记录常态）？
   └─ 是 → 两者都需自测；Laya 走多语言检查点 + Router
```

### 4.2 落地顺序（对齐路线图阶段）

| 步骤 | 内容 | 对应阶段 | 验收判据 |
|---|---|---|---|
| 1 | copilot 架构层接入（模型路由/输出验收），零标注起步 | 任意（不依赖产线数据） | 调用成本与延迟对比基线 |
| 2 | SPC 报警分诊**影子模式**：模型只给建议、人工照旧处置，日志全量留痕，跑 4-6 周 | S2 末 | 建议与人工处置一致率、分歧案例分析 |
| 3 | 用影子期积累的 (报警, 人工处置) 对做 Laya 微调 + 温度校准（Kaggle 2×T4，4-5h/轮） | S2→S3 | 自有测试集准确率 + ECE ≤0.1 |
| 4 | 阈值分级上线：高置信自动执行（仅限低风险动作如"标记待看"），低置信转人 | S3 | 误报率、人工工作量下降比例 |

### 4.3 风险清单

| 风险 | 事实依据 | 缓解 |
|---|---|---|
| 准确率不占优 | Jev 公开基准 0.72-0.87 全部低于对应最强 LLM 基线；Laya base 0.36 | 只替代"LLM/人工太贵"的判断，不追求比 LLM 准；阈值兜底 |
| 校准虚标 | Laya 裸 ECE 0.466；Jev 无官方 ECE（逆向 0.0313 仅 MMLU） | 自有分布温度拟合 + 分位数监控 |
| 接口不稳定 | Laya 三天 0.1.0→0.3.4；Jev 仍在 early access | 锁版本（`jev-1.13.0` 类 pin，别名换版本分布会变）；封装适配层 |
| 供应商风险 | Jev 闭源 v1、护城河存疑（社区数个周末级复现）；Laya 单人维护 | 决策层抽象（原语接口），底座可换 |
| 无解释性 | 不产推理链 | 影子模式 + 日志留痕 + 决策权留人 |
| 中文/中英混杂 | Jev 英语优先；Laya 45/51 语言但中文未单独验证 | 上线前用厂内真实记录自测 |

## 五、结论

1. **品类判断**：把"判断"从生成式模型里拆出来做成独立的一层（延迟降 1-2 个数量级、成本降 2-3 个数量级、输出类型安全），这个方向被生态快速验证（Vercel 原生 API、LangChain 实验、Gemma 跟进）——**作为架构趋势可信**。
2. **对先进封装厂**：近期（0-6 个月）价值在两处——copilot 架构层（零标注、无合规问题）与 SPC/FA 类文本判断的影子模式（有历史标注可用）；中期（6-18 个月）在微调后的本地 Laya 承接处置类任务。图像、数值判定、主链路控制三个方向明确不用它们。
3. **Jev 基本出局的原因是合规而非能力**：fab 数据分级与客户 IP 约束下，工艺文本出境这一条就否掉主用途；它的 64k 上下文与宽选项能力只在脱敏场景（公开文档 copilot）保留价值。
4. **Laya 是主路径但有三个前置**：GPU（T4 级即可）、历史标注（MES/FA 处置记录就是）、温度校准（不做则 confidence 不可用）。三个前置都在厂内可控范围内——这是"可以特化的本地专才"对封测场景的真正意义。
