## 00 四个说法与裁定总览

| # | 高频说法 | 判定 | 修正结论 |
|---|---|---|---|
| 1 | 数字 Bin 是 good，其他用 ASCII 字母/符号表示 function fail、电流 fail 等失效类别 | **命名惯例，非标准** | pass/fail 由 PART_FLG 标志位承载（bit3：0=pass、1=fail），与 bin 编号无关；STDF bin 编号仅有数字 0–32767；字母只能作为厂内格式/程序 bin 表中的 bin 名存在 |
| 2 | HBM 堆叠的"pre-DC 测试"要 10 小时左右 | **数字有出处，环节归属错误** | ~10h 的行业口径对应晶圆级老化（burn-in）；DC 参数测试为毫秒级/颗（STDF `TEST_T` 单位）；且"pre-DC"非行业术语 |
| 3 | 封装测试的主要问题就是 TCB 机台——机械臂抬升下压、抓取掉落 | **键合是主嫌之一，归因不完整** | Bridge/HIP 与 TCB 强相关，但 Crack 归减薄/切割/搬运、SealRing 归探扎/划片、TSV 归堆叠前的前道；"抬升下压/抓取掉落"分属键合压头、探针台、搬运三类设备 |
| 4 | T5833 靠电流就能检测出这些失效——靠的是测试电路设计还是程序设计？ | **问法需拆解为三层** | 被测芯片 DFT 电路解决可观测性，ATE 的 PMU 把电压/电流互译为判定位，测试程序负责顺序/限值/bin 编码；"电流检测"仅覆盖 DC 参数子集，功能失效靠图形比较 |

## 01 Bin 编号语义：命名惯例与标准机制的边界

### 1.1 标准机制：pass/fail 不在 bin 编号里

STDF V4 的 PRR（Part Results Record）每颗 die 一条记录，关键字段与位定义：

| 字段/位 | 定义 | 工程含义 |
|---|---|---|
| `HARD_BIN` | 数字，合法范围 0–32767 | 硬件 bin：决定 handler 物理分选去向 |
| `SOFT_BIN` | 数字，0–32767，缺失值 65535 | 软件 bin：承载更细的业务分类 |
| `PART_FLG` bit3 | **0 = Part passed，1 = Part failed** | pass/fail 的唯一权威判定；极性与直觉相反，解析时方向写反是最常见的入门错误 |
| `PART_FLG` bit4 | 0 = bit3 有效；1 = 无 pass/fail 结论 | 处理"测了但没有判定"的记录时必须检查 |
| `PART_FLG` bit2 | 0 = 正常结束；1 = 异常结束 | 异常结束的 die 不应计入良率分母 |
| `PART_FLG` bit0/1 | 重测/覆盖标志 | 同一 PART_ID（或同一 wafer 坐标）的新序列覆盖旧序列——复测数据处理的依据 |

三条结论：

1. **"这颗 die 是否 pass"由 PART_FLG 承载，与 bin 编号取值无关。**
2. **STDF 的 bin 编号只有数字**。字母形态的 bin 只存在于两处：厂内私有格式（WPFile 的 BinMap 标签）或程序 bin 表中的 bin **名**（字符串字段）。名字随程序走，不进标准编号。
3. bin 编号本身**无跨厂标准语义**——同一编号在不同程序中含义可以完全相反。

### 1.2 惯例对照：两种相反的 bin1 语义并存

| 惯例 | 内容 | 出处 |
|---|---|---|
| "数字 bin = pass 档" | SBin 1–9 默认全部为 pass grades（1 最优、9 最差，测试只能降档不能升档）——某测试框架的默认约定 | Semi-ATE binning 文档 |
| "bin1 = 失效" | DRAM 教学 bin 体系：fail-stop 顺序下 bin1 = Open/Short、bin2 = PowerShort…… | Edusemi（项目既有归档） |
| pass 按档、fail 按类 | pass die 按性能分档进 bin，fail die 按失效类型进 bin | NI TestStand 半导体模块 |
| Pass/Fail 为显式属性 | IEEE P1450.4 把 Pass/Fail 状态定义为 bin 定义的组成元素，而非由编号推导 | STIL P1450.4 binning 工作文件 |

两种相反的 bin1 语义并存，即是"编号无标准语义"的直接证明；P1450.4 的设计（状态作为显式属性）是标准组织对这一问题的正面回应。

### 1.3 工程规则

拿到一份新测试数据，先确认三件事再开始分析：

1. **bin 表**：bin → 含义映射，随测试程序版本走（版本变更需核对映射表）；
2. **pass/fail 标志位**：字段名与极性（尤其 STDF bit3 的 1=fail）；
3. **fail-stop 顺序**：决定 bin 分布形状——前面的 bin 挂了后面不测，raw bin 计数含删失偏差。

数据工程对照：bin 是 label encoding，码本随 pipeline 定义，label 数值大小不承载语义——换数据源必须换码本。

## 02 HBM 测试时长：~10h 的出处是 burn-in，量级须按环节拆分

### 2.1 出处定位

"10 小时"的行业口径来源：THE ELEC 引韩国 IR 协议会 2025 年报告——HBM burn-in（晶圆级老化）测试约 10 小时；HBM4 因 I/O 翻倍（1024→2048）与引脚速率提高，burn-in 时长预计至少增至 1.5 倍；同等 socket 数量下 burn-in 从 10h 增至 20h，出货量减半（原文以假设句式表述，属行业口径而非厂商规格，归档见 [`public/sources/hbm-test/2026-09-26_korea-press_hbm-test-duration.md`](/sources/hbm-test/2026-09-26_korea-press_hbm-test-duration.md)）。

同期检查环节的耗时口径：C-SAM 超声检查 1h/片（SK 海力士 2025-02 引入旋扫式后约 10min）；三维 CT 精检 5–6h（三星新装备目标 <1h）。

### 2.2 量级拆分：小时级总账由哪些环节构成

| 环节 | 量级 | 依据 |
|---|---|---|
| DC 参数单项（接触/开短路/漏电/Idd） | 毫秒级/项·die | μA–mA 级施加与回测；STDF `TEST_T` 单位为毫秒/颗 |
| 单次接触 | 6s/次 | HBM2 KGDS 微凸点直接扎针实验（SWTest 2019 FormFactor） |
| 单次插入的电测全流程 | 秒–分钟级/颗 × 晶圆并行度 | T5833 晶圆并行 1,024/2,048；M7H 高同测 |
| 晶圆级老化（WLBI/burn-in） | **小时级（行业口径 ~10h，HBM4 预计 ≥1.5×）** | THE ELEC 引研报 |
| 高低温双温、修复后复验 | 随插入次数线性累加 | 三星 EDS 五步流程（项目既有归档） |
| 全流程（12 层堆栈） | **3–12 次测试插入** | SemiEngineering 2026-05 |

### 2.3 结论与术语纪律

- "10 小时"真实存在，但它属于 **burn-in（老化）**，把等式写成"DC 测试 = 10 小时"属于环节错配。
- **"pre-DC"不是行业通用术语**。若指堆叠前（pre-stack）电测，它是 DC 参数 + 功能 + 修复 + 复验的整段流程；其中只有老化与多温环节为小时级。
- 引用纪律：时长数字必须携带环节定语——"电测毫秒级/颗、老化小时级/片、检查小时级/片、全流程 3–12 次插入"。

## 03 封装失效归因：键合是主嫌之一，"都是 TCB 的问题"不成立

### 3.1 背景：HBM 封装相关失效占比确实高

Synopsys 引超大规模云厂数据：HBM 失效是数据中心 GPU 失效的第一大原因；堆叠键合对准精度在 ±1.4μm 量级（FormFactor/Advantest SWTest 2025）；12–16 层堆叠的良率复利使单 die 良率损失被放大 6–7 倍。"封装相关失效占比高"成立——但这不等于"都是 TCB 机台的问题"。

### 3.2 责任工序归属

| 物理根因 | 责任工序 | 与 TCB 键合机的关系 |
|---|---|---|
| 凸点 Bridge / head-in-pillow | 键合（TCB / MR-MUF / TC-NCF） | **强相关**——对准、压力、温度曲线 |
| PowerShort（VDD–VSS 桥） | 键合材料挤压 **或** 前道金属残留 | 待定——需位图/FA 定责 |
| Crack（裂纹） | 减薄 / 切割 / 搬运应力 | 无关（30–50μm 薄片对机械应力更敏感） |
| SealRing 损伤 | 探针扎痕 / 划片 | 无关（IPFA 2021 实证：探痕可致分选失效） |
| TSV 开路（column fail） | TSV 刻蚀/铜填充（堆叠之前的前道工序） | 无关——发生在 TCB 上料之前 |

### 3.3 设备语义拆解："抬升下压、抓取掉落"分属三类设备

| 设备 | 环节 | 动作 | 典型损伤与电测签名 |
|---|---|---|---|
| TCB 键合机（ASMPT/Besi 等） | 键合 | 加热加压完成堆叠 | bridge/HIP/高阻/对准偏移——邻位短路、随机分布 HIP |
| 探针台 + ATE（prober + tester） | 电测 | 上下针扎取——prober 也有抬升下压，但那是**测试接触**，不是键合 | 探痕、扎偏——沿边开路/漏电 |
| handler / die carrier / 周转 | 搬运 | 抓取、吸放、传送 | 崩边、跌落裂纹——边缘环、开路簇 |

"暴露失效的环节 ≠ 肇事环节"：TCB 键合的产物缺陷要等下游测试插入点才暴露；搬运损伤在电测留下特定空间签名。归因方法 = **电测签名 × 空间签名 × 跨插入点差分**（CP 过、堆叠后挂 → 键合/减薄类），最终 X-ray/SAT/切片物理分析闭环。

## 04 "电流为什么能测出失效"：DC 参数测试的三层可观测性链

T5833（ATE）不"知道"失效，它只执行施加与测量。"能测出来"由三层设计在芯片出厂前决定：

### 4.1 第 1 层：被测芯片的 DFT 电路设计——解决可观测性

| 结构 | 作用 |
|---|---|
| ESD 保护二极管 | 每个焊盘对地的二极管对是接触/开短路测试的测量靶子——设计期即存在 |
| MBiST 引擎 | base die 上的图形发生器 + 比较器 + 失效捕获存储，把阵列/TSV/lane 状态转化为图形比对结果 |
| IEEE 1500 wrapper + DA 端口 | HBM2 堆栈 3990 凸点中划出 176 个直接访问凸点作为测试入口，把堆栈深处的可观测性引到可扎针位置 |
| TSV 感测 + fuse box | TSV 连通性可感测，坏 lane 可重映射修复 |

设计期决定"哪些问题**可以**被问"——没有这一层，ATE 无法观测堆栈内部。

### 4.2 第 2 层：ATE 的测量电路（PMU）——把物理量变成判定位

PMU（每引脚一个）两种模式 + 钳位 + 窗口比较器（量程档 ±2μA–±50mA，ADI MAX9979）：

| 失效类型 | 模式 | 操作 | 健康读数 | 失效读数 | 判定 |
|---|---|---|---|---|---|
| 接触/开路 | FIMV（加流测压） | 对 pin–GND 二极管加 ~100μA | V ≈ 0.6–0.7V（PN 结导通） | 电流无路径，V 顶到钳位 | Open/Short |
| 对地短路 | FIMV | 同上 | 同上 | V ≈ 0（二极管被旁路） | Open/Short |
| PowerShort / 漏电 | FVMI（加压测流） | 电源轨/引脚加 spec 电平 | I 在 μA–mA 限内 | I 超限 | DC 致命类 |

"电流检测出失效"的物理本质：强制电流注入后，电压读数暴露电流路径状态——欧姆定律 + PN 结特性 + 钳位比较，无额外机制。

### 4.3 第 3 层：测试程序设计——判定与编码

fail-stop 顺序（Contact → PowerShort → Idd → Function → Margin，先致命后边角）、逐项上下限、bin 赋值、修复决策。同一台 T5833，换一版程序，bin 分布形状随之改变。

### 4.4 边界：电流检测只覆盖 DC 参数子集

功能位失效、TSV column fail 靠 APG 图形经 MBiST 比较（数字图形比对，非电流测量）；高速 lane 靠 at-speed 图形经 DA 端口复用 PHY。完整表述：**DFT 解决可观测性，PMU 完成物理量到判定位的转换，程序负责判定与编码——三层缺一不可。**

### 4.5 与数据工程概念的对照

| 半导体测试 | 数据工程 |
|---|---|
| DFT 测试电路（二极管靶子/MBiST/DA 端口） | 埋点与日志设计——先保证可观测 |
| PMU（FVMI/FIMV + 钳位 + 窗口比较器） | 采集探针——物理状态到结构化数值 |
| 测试程序（fail-stop/limit/bin） | pipeline 编排 + 阈值规则 + 输出编码 |
| bin 表 | 枚举字典/码本 |
| WPFile（厂内私有）vs STDF（行业标准） | 私有日志格式 vs 开放标准格式 |
| 良率趋势/Pareto/热力图 | BI 看板与指标下钻 |

## 05 方法论：未核实数字的三步溯源

1. **术语锚定**：自造词/缩写先对标准词表（"pre-DC"查无此术语 → 拆为 pre-stack 电测与 DC 参数分别查证）。
2. **出处回溯**：数字必须追到原始语境（"10h"回溯到 THE ELEC 引研报 → 语境是 burn-in 而非 DC）。数字离开语境即产生环节错配。
3. **信号链拆解**：谁产生信号（DFT）→ 谁测量（PMU）→ 谁判定（程序）→ 谁编码（bin 表）。链路闭合后无需诉诸"神奇"。
